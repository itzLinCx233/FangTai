# 测试说明（简易版）

四层测试体系：单元测试 → 全量评测（功能/性能分模式）→ 赛题评分自测 → DeepSeek 包装脚本。

## 一图流

| 脚本 | 测什么 | 依赖 | 产出 |
|---|---|---|---|
| `tests/test_core.py` | 核心纯逻辑（解析/约束/营养/组合/槽位/优先级） | 无 LLM、无网络，秒级 | 控制台 |
| `scripts/eval.py` | 20 组对话用例 + 内置冲突场景，功能与性能分模式 | LLM + 百炼 Key | `--out` 指定报告 |
| `scripts/score_test.py` | 赛题 100 分制四大项（①②③走 API，④读 eval 报告） | 需起服务 | `score_report.json` |
| `scripts/test_deepseek.sh` | eval.py 的 DeepSeek(deepseek-flash) 环境包装 | `.keys.env` 或环境变量 | `eval_report_deepseek.json` |

## eval.py 两种模式（功能与性能分开跑）

```bash
python scripts/eval.py --mode func --out eval_func.json   # 功能测试
python scripts/eval.py --mode perf --out eval_perf.json   # 性能测试
python scripts/eval.py                                    # both：全量+冲突（历史口径）
```

- **func 功能测试**：跳过简单场景（单轮 + 无追加约束槽位 + 无模糊需求词，
  如"今晚吃啥""帮我安排两人晚餐"——这类只走基础推荐流程，已由 score_test
  的 50 档案全量覆盖），保留多轮/多约束/模糊需求用例，并**强制跑冲突场景**。
- **perf 性能测试**：全量 20 用例计时（29 轮口径与历史报告可比），跳过冲突场景。
  性能档位：首Token/单轮/多轮均值，优秀 <2s/<8s/<6s，合格 <5s/<15s/<12s。
- `test_deepseek.sh` 默认 `LLM_THINKING=disabled`（关闭思考，单轮 ~3s，测试快）；
  质量优先复测时显式覆盖：`LLM_THINKING=high bash scripts/test_deepseek.sh ...`。
- `--case N` 只跑指定用例（冒烟）；`--api http://...` 走 HTTP SSE 而非进程内。

## 内置冲突场景（901/902/903/905/910/911，func 模式必跑）

验证"对话追加约束优先于档案人设"，过敏/疾病忌口属安全约束**永不解除**（赛题零违反口径）。

| id | 场景 | 判定 |
|---|---|---|
| 901 | 档案口味清淡 vs 对话要辣（user3） | 末轮推荐含辣菜且花生过敏零违反 |
| 902 | 先禁辣后要辣，最新对话优先（user37） | "辣"会话忌口被解除，鸡蛋过敏零违反 |
| 903 | 无烤箱/空气炸锅不给烤炸菜（user7） | 全程无烤制/炸制菜品 |
| 905 | 同句原样重复输入（user7） | 第2轮与第1轮菜品零交集（重复提问也换新菜） |
| 910 | **人设模拟**：无烤箱家庭想喝汤（单轮） | LLM 扮演用户生成消息；无烤炸菜+末轮有汤 |
| 911 | **人设模拟**：饭后才想起没烤箱（两轮） | 约束后置+加汤；旧烤菜被替换、无烤炸、有汤、新菜不与首轮重复 |

人设模拟场景（`persona` 字段）：场景只定义**人设要点**与**结构化断言**
（`expect: banned_methods / require_soup / norepeat_new`），用户消息由
`chat_fast` 扮演生成——措辞每次不同（temperature=0.8），要点必达，
断言固定可判定；生成消息记录在报告 `turns[].message` 与控制台 `[sim]` 行，
LLM 失败自动回退要点原文。

## 评测校验口径

- **零违反** = 档案过敏/疾病忌口（`allergen_violations`）+ 会话累积追加忌口
  （`session_banned_violations`，如"别做辣的"）双双为零；报告分列统计。
- **零幻觉** = plan 每道菜 `store.find_by_name` + id 校验存在。
- **跨轮去重** = 非沿用（`kept=false`）的新选菜不得是本会话历轮推荐过的
  （`repeat_dishes_total`；系统侧由 `DialogSession.served_ids` 检索排除实现，
  reject_all 换桌也不吃回头菜）。
- **设备约束** = "没有烤箱"→禁 `cook_method=烤` 及步骤含"烤箱"的菜；
  "没有空气炸锅"→禁"炸"。
- **口味冲突遵循** = 对话最新正向口味覆盖档案口味偏好与旧会话忌口
  （`taste_followed_dialog`）。

## 常用命令

```bash
.venv/bin/python tests/test_core.py                    # 单测（pytest 也可）
bash scripts/test_deepseek.sh --case 15                # DeepSeek 冒烟（1用例+4冲突）
bash scripts/test_deepseek.sh --mode func --out eval_func_deepseek.json
python scripts/score_test.py --api http://127.0.0.1:8000        # 评分自测
python scripts/score_test.py --skip-basic --eval eval_perf.json # 跳过50档案+指定性能报告
```

改 `app/core/` 后必须：单测通过 + 冒烟（`--case` + 冲突场景）通过再提交。
